# @cf4u/db

Drizzle schema + migrations. Translated from `docs/schema.sql` — **all CHECK / trigger / role preserved**.

## Two connection strings (铁律 5)

| Env var | Role | Used by |
|---|---|---|
| `DATABASE_URL` | admin / owner | migrations, `verify`, `seed` (can `CREATE ROLE` + own triggers) |
| `APP_DATABASE_URL` | `ledger_app` | application runtime only — `audit_log` is SELECT-only |

Fill both in the repo-root `.env` (see `.env.example`).

## Step 2 runbook

```bash
# 1. apply migrations (tables + extensions, then triggers/role)
pnpm --filter @cf4u/db migrate

# 2. set a password for the app role so APP_DATABASE_URL can log in
#    (migration creates `ledger_app LOGIN` without a password)
psql "$DATABASE_URL" -c "ALTER ROLE ledger_app PASSWORD '<pick-one>';"
#    then put that password into APP_DATABASE_URL in .env

# 3. verify the red-line invariants actually hold
pnpm --filter @cf4u/db verify
```

`verify` proves, against the live DB:

- **铁律 3** — `trg_balanced` + `trg_balanced_on_post` are DEFERRABLE INITIALLY DEFERRED and
  reject unbalanced / empty entries on post (balanced entry posts fine). Functional, run inside a
  transaction that is rolled back — leaves no test data.
- **铁律 5** — `write_audit()` auto-logs a ledger write with the actor from `app.user_id`, and
  `ledger_app` has exactly `{SELECT}` on `audit_log` (INSERT denied on a live `ledger_app` connection).

Exit code is non-zero if any check fails.

## Migrations

- `drizzle/0000_*.sql` — extensions + 17 tables (generated by `drizzle-kit generate` from `src/schema.ts`).
- `drizzle/0001_triggers_roles.sql` — hand-authored: 2 balance constraint triggers, `write_audit()`
  + 5 audit triggers, `ledger_app` role with GRANT/REVOKE. **Verbatim from `docs/schema.sql`.**

Regenerating tables: edit `src/schema.ts`, then `pnpm --filter @cf4u/db generate`. The hand-authored
`0001` is never regenerated — keep the red-line objects there.
